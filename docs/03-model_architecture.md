# 步骤 3: StockMixer 模型架构实现 (`model.py`)

本节将指导您实现 StockMixer 模型的网络架构。该模型主要由 MLP（多层感知机）块构成，用于混合不同维度的信息：指标混合、时间混合和股票混合。

## 3.1 MLP 混合器基类/模块

**任务**: 设计并实现一个通用的 MLP 混合器模块。根据论文描述，StockMixer 的核心是 MLP 块。这些 MLP 块在不同的维度（指标、时间、股票）上操作，但其基本结构可能相似：通常包含两个全连接层，中间有一个激活函数 (如 GELU)，并可能包含层归一化 (Layer Normalization) 和残差连接 (Residual Connection)。

**提示词 (针对 LLM)**:
"我正在实现 StockMixer 模型，其核心是 MLP 混合器。请帮我设计一个基础的 MLP 模块（例如，一个 PyTorch `nn.Module` 子类），它应具备以下特性：
1.  输入是一个张量。
2.  包含两个线性（全连接）层。
3.  在两个线性层之间有一个激活函数（例如 GELU，可配置）。
4.  能够对输入张量在指定的维度上进行操作（即混合操作）。这意味着 MLP 层的权重是针对该维度共享的，还是每个元素独立处理，需要明确。
5.  可选地包含层归一化 (Layer Normalization)。
6.  可选地包含残差连接。

请描述这个基础 MLP 模块的构造函数参数（例如，输入维度、隐藏维度、激活函数类型、是否使用层归一化和残差连接）以及其 `forward` 方法的逻辑。特别说明 MLP 如何应用于特定维度（例如，如果输入是 `[batch, stocks, time_steps, features]`，MLP 是应用于 `features` 维度，还是 `time_steps` 维度等，以及如何通过调整张量形状或使用特定操作来实现这一点）。不要提供具体的 Python 代码。"

**测试方法**:
- **单元测试**:
    - 准备创建一个名为 `test_mlp_mixer_block.py` 的测试文件。
    - 在该文件中，实例化您设计的 MLP 混合器模块，并使用不同形状和值的 mock 输入张量进行测试。
    - **测试用例 1 (形状)**: 验证模块输出张量的形状是否符合预期（通常情况下，混合操作不改变除被混合维度之外的其他维度的大小，除非有显式的降维或升维）。
    - **测试用例 2 (简单计算)**: 使用非常小的、已知的权重和输入，手动计算预期输出，并与模块的实际输出进行比较，以验证计算逻辑的正确性（特别关注激活函数、层归一化和残差连接的影响）。
    - **测试用例 3 (不同维度操作)**: 如果 MLP 模块设计为可以在不同维度上操作，请测试其在不同指定维度上操作时的行为是否符合预期。

## 3.2 指标混合 (Indicator Mixing)

**任务**: 实现指标混合模块。这一步是在每个时间步内，混合不同市场指标（特征）的信息。

**背景信息**: 输入数据的特征维度 (例如，开盘价、收盘价、RSI 等) 需要被混合。

**提示词 (针对 LLM)**:
"基于之前设计的 MLP 混合器基类，我现在需要实现 StockMixer 的第一个组件：指标混合模块。
- **输入**: 一个张量，形状类似于 `[N, S, T, C]` (批次大小 N, 股票数量 S, 时间步长 T, 特征/通道数量 C)。
- **操作**: 对于每只股票的每个时间步，使用 MLP 混合器沿特征维度 `C` 进行混合。
- **输出**: 一个张量，形状应与输入相同 `[N, S, T, C]`（或者如果MLP改变了输出特征数，则为 `[N, S, T, C']`）。

请描述这个指标混合模块的结构，它如何使用基础 MLP 模块，以及数据在模块中是如何流动的。说明层归一化和残差连接是否适用于此阶段。"

**测试方法**:
- **单元测试**:
    - 准备创建一个名为 `test_indicator_mixer.py` 的测试文件（或在 `test_model_components.py` 中添加测试）。
    - 实例化指标混合模块。
    - 使用一个形状为 `[N, S, T, C]` 的 mock 输入张量。
    - 验证输出张量的形状是否为 `[N, S, T, C']` (如果输出特征数改变) 或 `[N, S, T, C]` (如果不变)。
    - 检查混合操作是否确实在特征维度上发生（例如，通过比较不同特征通道在输出中是否被整合）。

## 3.3 时间混合 (Temporal Mixing)

**任务**: 实现时间混合模块。这一步是在每个股票的每个指标上，混合不同时间步的信息。

**背景信息**: 在指标混合之后，模型需要在时间维度上捕捉模式。

**提示词 (针对 LLM)**:
"接下来是 StockMixer 的时间混合模块。
- **输入**: 指标混合模块的输出，形状类似于 `[N, S, T, C']`。
- **操作**: 对于每只股票的每个特征通道，使用 MLP 混合器沿时间维度 `T` 进行混合。
- **输出**: 一个张量，形状应与输入相同 `[N, S, T, C']`（或者如果MLP改变了输出时间步数，则为 `[N, S, T', C']`，但通常时间混合不改变时间步数量，而是学习时间依赖性）。

请描述这个时间混合模块的结构，它如何使用基础 MLP 模块，以及数据流。说明层归一化和残差连接是否适用于此阶段。"

## 3.5 StockMixer 整体模型 (`StockMixer` 类)

**任务**: 将上述所有混合器模块以及可能的其他层（如初始嵌入层、最终输出层）组合成完整的 `StockMixer` 模型。

**背景信息 (`train.py` 中的模型初始化)**:
`StockMixer(stocks=stock_num, time_steps=lookback_length, channels=fea_num, market=market_num, scale=scale_factor)`
这表明模型构造函数需要接收股票数量、时间步长、特征通道数等参数。
`market_num` 和 `scale_factor` 的具体作用需要根据论文或 `model.py` 的实现细节来确定，它们可能是用于调整 MLP 内部维度或层数。

**提示词 (针对 LLM)**:
"我现在要将指标混合、时间混合和股票混合模块组合成一个完整的 `StockMixer` PyTorch 模型 (`nn.Module` 子类)。请基于以下信息，描述这个 `StockMixer` 类的结构：
- **构造函数参数**: 参考 `train.py` 中的实例化：`stocks` (股票数量 S), `time_steps` (时间步长 T), `channels` (输入特征/通道数量 C), `market` (可能用于调整 MLP 内部维度或层数的一个参数), `scale` (同上，可能用于 MLP 内部维度)。请推测这些参数如何影响模型内部各组件的配置（例如，MLP 的隐藏层大小）。
- **模型流程 (`forward` 方法)**:
    1.  输入数据形状：`[N, S, T, C]` (原始批次数据，其中 N 是批次中的样本数，但原始 `train.py` 中的 `get_batch` 返回的 `eod_data` 是 `[S, T, C]`，在训练循环中 N 似乎是1，或者批处理方式不同，需要明确模型期望的输入)。假设模型期望的输入是 `[S_batch, T_batch, C_batch]` (对应一个或多个股票在一段时间内的特征)。 **更正**：从 `train.py` 的 `model(data_batch)` 来看，`data_batch` 的形状是 `[stock_num, lookback_length, fea_num]`，即 `[S, T, C]`。
    2.  数据依次通过：指标混合层 -> 时间混合层 -> 股票混合层。
    3.  可能在这些混合层之间或之后有额外的处理层，例如用于调整输出维度以匹配预测目标的全连接层。
    4.  最终输出：模型的预测结果，其形状应为 `[S, 1]` (每只股票一个预测值，对应 `gt_batch` 的形状)。

请描述 `StockMixer` 类的构造函数如何初始化这些组件，以及 `forward` 方法中数据是如何依次通过这些组件并最终产生预测输出的。特别说明参数如 `market` 和 `scale` 可能如何影响MLP块的配置。"

**测试方法**:
- **单元测试**:
    - 准备创建一个名为 `test_stockmixer_model.py` 的测试文件。
    - 实例化完整的 `StockMixer` 模型，使用一些预定义的参数值。
    - **测试用例 1 (前向传播和输出形状)**:
        - 创建一个符合模型输入期望形状的 mock 输入张量 (例如，`[stock_num, lookback_length, fea_num]`)。
        - 执行模型的前向传播 (`model(input_tensor)`)。
        - 验证输出张量的形状是否为 `[stock_num, 1]` (或者与 `gt_batch` 的形状一致)。
    - **测试用例 2 (参数影响)**: (较复杂) 如果可能，尝试改变构造函数参数（如 `market`, `scale`），并观察（或通过辅助函数检查）模型内部 MLP 层的维度是否按预期发生变化。这可能需要模型设计时允许外部检查内部组件的配置。
    - **测试用例 3 (梯度检查)**: (高级) 在一个极小的模型和输入上，执行一次前向和反向传播（需要一个虚拟的损失函数和目标），并检查模型参数是否有梯度流动。这有助于确保所有层都正确连接并且参与到计算中。
