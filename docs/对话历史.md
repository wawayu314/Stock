非常好！我们这就开始第一个创新点：“多尺度时间特征提取”。

这个创新点的核心思想是让模型能够从不同时间尺度（或分辨率）捕捉输入序列的特征，并将这些信息融合起来，以期获得更丰富的时序表征。

为了实现这一点，我将对 `src/model.py` 文件进行修改。这些修改主要包括：

1.  **增强 `TriU` 模块的稳健性**：
    *   确保 `TriU` 模块在初始化时如果 `time_step` 为0能够正确处理。
    *   在 `TriU` 的 `forward` 方法中，使其能够灵活处理输入时间维度与初始化 `time_step` 不完全匹配的情况，特别是当输入时间维度较小时，避免索引错误。

2.  **定义辅助模块**：
    *   `PermuteForConv1d`：将张量从 `(batch, time, channel)` 转换为 `(batch, channel, time)` 以便 `Conv1d` 处理。
    *   `PermuteFromConv1d`：将张量从 `(batch, channel, time)` 转换回 `(batch, time, channel)`。
    *   `PermuteAndApplyTriUNet`：一个封装了标准模式的模块，即将输入先置换维度，然后通过一个基于 `TriU` 的网络（例如 `TriU -> Activation -> TriU`），最后再置换回原始维度顺序。这使得 `TriU` 网络可以方便地作用于时间维度。

3.  **实现新的多尺度时间混合模块 `MultiScaleTimeMixerRevised`**：
    *   它会包含多个处理分支：一个分支直接处理原始时间尺度的输入，其他分支通过一维卷积（`Conv1d`）对输入进行下采样，然后在这些不同尺度的时间序列上分别进行处理。
    *   每个分支内部会使用 `LayerNorm` 和一个 `TriU -> Hardswish -> TriU` 结构来处理时间序列。
    *   不同 `TriU` 实例会根据其对应分支处理的时间步长被正确初始化。
    *   最后，所有分支的输出将在时间维度上拼接（concatenate）起来，形成一个更丰富的多尺度时间表征。

4.  **更新 `StockMixer` 主模型**：
    *   在 `__init__` 方法中：
        *   根据传入的 `scale` 参数（它将代表期望的总尺度数量）动态构建一个 `scales_config` 列表，用于配置 `MultiScaleTimeMixerRevised` 的各个分支（如每个卷积分支的步长、卷积核大小以及处理后的时间步长）。
        *   计算所有尺度拼接后的总时间维度 `concat_time_dim`。
        *   使用 `MultiScaleTimeMixerRevised` 实例替换原有的时间混合逻辑。
        *   更新后续的全连接层，如 `self.time_fc` 和 `self.time_fc_`，使其输入维度与 `concat_time_dim` 匹配。
        *   `NoGraphMixer` 的实例化方式 `NoGraphMixer(stocks, market)` 保持不变，因为它本身设计为对 `stocks` (即`stock_num`) 这个维度进行混合，而其输入 `y_channel_processed` 将会是 `(stock_num, concat_time_dim)` 的形状，这与 `NoGraphMixer` 的内部处理逻辑是吻合的。
    *   在 `forward` 方法中：
        *   调整数据流以正确通过新的 `MultiScaleTimeMixerRevised`。
        *   确保后续模块（如 `channel_fc` 和 `NoGraphMixer`）接收到正确形状的张量。

我将修改 `TriU` 的 `forward` 方法，增加对 `time_step == 0` 的处理，并确保在循环中使用的 `time_step` 不会超出输入张量的实际维度。



```python

class TriU(nn.Module):
    def __init__(self, time_step):
        super(TriU, self).__init__()
        self.time_step = time_step
        if self.time_step < 0:
            raise ValueError("time_step cannot be negative")
        
        self.triU = nn.ParameterList(
            [
                nn.Linear(i + 1, 1)
                for i in range(self.time_step) # Corrected: self.time_step, not time_step
            ]
        )

    def forward(self, inputs):
        # inputs shape: (batch, channels, time_actual) or (batch, time_actual, features)
        # TriU is designed to work on the last dimension.
        
        if self.time_step == 0:
            # Return an empty tensor with correct batch and channel/feature dims, but 0 time dim.
            # Assuming inputs has at least 3 dimensions (B, C, T) or (B, T, F)
            if inputs.ndim < 2:
                 raise ValueError("Input tensor must have at least 2 dimensions for TriU")
            # For (B, C, T_actual), output (B, C, 0)
            # For (B, T_actual, F), output (B, 0, F) - this case is less likely for TriU's intent
            # Based on typical usage (e.g., after permute to B,C,T), let's assume last dim is time.
            output_shape = list(inputs.shape)
            output_shape[-1] = 0
            return torch.empty(output_shape, device=inputs.device, dtype=inputs.dtype)

        actual_input_time_dim = inputs.size(-1)
        
        # effective_time_step is the number of TriU layers we can actually apply
        # or the number of outputs we will generate.
        effective_time_step = min(self.time_step, actual_input_time_dim)

        if effective_time_step == 0: # handles cases like actual_input_time_dim = 0 but self.time_step > 0
            output_shape = list(inputs.shape)
            output_shape[-1] = 0
            return torch.empty(output_shape, device=inputs.device, dtype=inputs.dtype)

        # Apply the first linear layer. inputs are (batch, channels, time_dim)
        # self.triU[0] is Linear(1,1). It needs input of shape (*, 1)
        # inputs[:, :, 0] is (batch, channels). unsqueeze(-1) makes it (batch, channels, 1)
        current_slice = inputs[..., 0:1] # Takes the first element along the last dimension
        x = self.triU[0](current_slice) 
        
        for i in range(1, effective_time_step):
            # self.triU[i] is Linear(i+1, 1)
            # It needs input of shape (*, i+1)
            # inputs[..., 0:i+1] provides a slice of shape (batch, channels, i+1)
            current_slice = inputs[..., 0:i+1]
            processed_slice = self.triU[i](current_slice)
            x = torch.cat([x, processed_slice], dim=-1)
        return x
```

```python
        x = self.dense2(x) # Output (num_stocks, num_stocks_orig_passed_to_init)
        x = x.permute(1, 0) # (num_stocks_orig_passed_to_init, num_stocks)
        return x


class PermuteForConv1d(nn.Module):
    """Permutes a (batch, time, channel) tensor to (batch, channel, time)."""
    def forward(self, x):
        return x.permute(0, 2, 1)


class PermuteFromConv1d(nn.Module):
    """Permutes a (batch, channel, time) tensor back to (batch, time, channel)."""
    def forward(self, x):
        return x.permute(0, 2, 1)


class PermuteAndApplyTriUNet(nn.Module):
    """Permutes to (B, C, T), applies a TriU-based net, and permutes back to (B, T, C)."""
    def __init__(self, triu_net_module, operates_on_last_dim=True):
        super().__init__()
        self.triu_net_module = triu_net_module
        self.operates_on_last_dim = operates_on_last_dim
    
    def forward(self, x):
        # x is expected as (B, T, C)
        if not self.operates_on_last_dim:
             # If TriU net expects (B, Features, Time) where Time is last dim
             # and our input x is (B, Time, Features), we need to permute for TriU
            x_permuted_for_triu = x.permute(0, 2, 1) # (B, C, T)
            processed_x = self.triu_net_module(x_permuted_for_triu) # Output (B, C, T')
            return processed_x.permute(0, 2, 1) # (B, T', C)
        else:
            # If TriU net expects (B, Something, Time_to_process_as_last_dim)
            # and input is (B, T, C), but we want to process C as the "time" for TriU
            # This case is less likely for typical TriU usage on time series.
            # Assuming typical use: TriU processes the last dim as time.
            # So, if input x is (B,T,C), and TriU is to process T, then TriU needs (B,C,T)
            # This path means the triu_net_module itself expects (B, T, C) and processes C. Unusual.
            # Let's stick to the primary intention: processing time dimension.
            # The default TriU processes the last dimension. If x is (B,T,C), it processes C.
            # To process T with TriU, we need (B,C,T). So PermuteAndApplyTriUNet handles this.
            
            # This module's main job is to ensure input to triu_net_module is (B, C, T)
            # and output is converted back from (B, C, T') to (B, T', C)
            x_permuted = x.permute(0, 2, 1) # (B, C, T)
            processed_x = self.triu_net_module(x_permuted) # Output (B, C, T_processed)
            return processed_x.permute(0, 2, 1) # (B, T_processed, C)
```

```python
            current_processed_time_steps = scale_info['time_steps']
```

```python
class StockMixer(nn.Module):
    def __init__(self, stocks, time_steps, channels, market, scale, activation_fn_class=nn.Hardswish):
        """
        stocks: Number of stocks (e.g., stock_num from train.py).
        time_steps: Initial lookback length (e.g., lookback_length from train.py).
        channels: Number of input features per stock per time step (e.g., fea_num from train.py).
        market: Used for NoGraphMixer hidden dimension (e.g., market_num from train.py).
                Note: In the original NoGraphMixer, the second param is hidden_dim.
        scale: The *target total number of scales* including the original. 
               E.g., scale=1 means only original. scale=3 means original + 2 conv scales.
        activation_fn_class: The class of the activation function to use (e.g., nn.Hardswish, nn.GELU).
        """
        super(StockMixer, self).__init__()

        self.scales_config = []
        calculated_concat_time_dim = 0

        # 1. Original Scale (always present)
        self.scales_config.append({
            'type': 'original',
            'time_steps': time_steps # Time steps for TriU in this branch
        })
        calculated_concat_time_dim += time_steps

        # 2. Convolutional Scales
        # `scale` parameter indicates the *total* desired number of scales.
        # If scale is 1, only original. If scale is 2, original + 1 conv. If 0 or less, only original.
        num_conv_scales_to_add = max(0, scale - 1)

        for i in range(num_conv_scales_to_add):
            # For the first conv scale (i=0 here), use 2**(i+1) to get stride/kernel of 2, 4, 8...
            # This ensures strides are 2, 4, 8... for successive conv layers.
            current_stride = 2**(i + 1)
            current_kernel = 2**(i + 1) # Non-overlapping windows usually have kernel == stride

            # Time steps after this convolution
            # Using integer division. Example: 16 // 2 = 8. 16 // 4 = 4.
            ts_after_conv = time_steps // current_stride

            if ts_after_conv >= 1: # Only add scale if it results in at least 1 time step
                self.scales_config.append({
                    'type': 'conv',
                    'kernel': current_kernel,
                    'stride': current_stride,
                    'time_steps': ts_after_conv # Time steps for TriU in this branch
                })
                calculated_concat_time_dim += ts_after_conv
            else:
                # If a scale results in < 1 time step, stop adding more conv scales
                # as they would be even smaller or zero.
                break
        
        if not self.scales_config or calculated_concat_time_dim == 0:
            raise ValueError(
                f"StockMixer init: No valid scales generated. "
                f"Initial time_steps: {time_steps}, requested total scales: {scale}. "
                f"Resulting concat_time_dim: {calculated_concat_time_dim}. "
                "Ensure time_steps is large enough for the requested number of scales."
            )

        self.temporal_mixer = MultiScaleTimeMixerRevised(
            initial_time_steps=time_steps,
            channels=channels,
            scales_config=self.scales_config,
            activation_fn_class=activation_fn_class
        )
        
        # This FC layer reduces the channel dimension to 1 after multi-scale time mixing.
        # Input: (B, calculated_concat_time_dim, C) 
        # Output: (B, calculated_concat_time_dim, 1) -> squeezed to (B, calculated_concat_time_dim)
        self.channel_fc = nn.Linear(channels, 1)
        
        # This FC layer processes the time-mixed, channel-reduced output.
        # Input: (B, calculated_concat_time_dim)
        # Output: (B, 1) for the y_out path
        self.time_fc = nn.Linear(calculated_concat_time_dim, 1)
        
        # NoGraphMixer mixes across the `stocks` dimension.
        # Its input will be (B, S_to_mix), where S_to_mix is `stocks` (stock_num)
        # and each of these S_to_mix elements has `calculated_concat_time_dim` features before this mixer.
        # However, NoGraphMixer as defined takes (num_features_to_mix_for_each_stock, hidden_dim)
        # The input to NoGraphMixer in the original code was `y` of shape (B, stock_num) after channel_fc and time_fc.
        # Let's re-evaluate the NoGraphMixer part based on the paper's Fig 1 and revised temporal_mixer.

        # After temporal_mixer, output is (B, calculated_concat_time_dim, C)
        # After channel_fc, output is (B, calculated_concat_time_dim)
        # This (B, calculated_concat_time_dim) is for EACH stock. 
        # The input to StockMixer forward is (B, T, C) where B is stock_num.
        # So, y_channel_processed is (stock_num, calculated_concat_time_dim)

        # Here, features_per_stock is calculated_concat_time_dim.
        # The `stocks` parameter to NoGraphMixer __init__ should be `calculated_concat_time_dim`
        # The `hidden_dim` parameter to NoGraphMixer __init__ can be `market` (as in original) or a new param.
        # Let's rename `market` in StockMixer to `stock_mixer_hidden_dim` for clarity if it's used for that.
        # Original: self.stock_mixer = NoGraphMixer(stocks, market) -> NoGraphMixer(stock_num, market_num)
        # This implies NoGraphMixer operated on (stock_num, some_feature_dim) and mixed along stock_num.
        # The input to NoGraphMixer in original StockMixer.forward was `y` of shape (B, stock_num)
        # This `y` was output of self.time_fc(self.channel_fc(y).squeeze(-1)) - so (B,1) -> error here.

        # Let's follow the revised logic: 
        # temporal_mixer output: (batch_of_stocks, concat_time, channels)
        # y_channel_processed: (batch_of_stocks, concat_time) after channel_fc and squeeze
        
        # NoGraphMixer should mix along the batch_of_stocks dimension.
        # So its input should be (concat_time, batch_of_stocks) after permutation.
        # Thus, NoGraphMixer's first init arg (num elements in the dim it mixes) should be `stocks` (i.e. stock_num).
        # And its second init arg (hidden_dim) can be `market` (i.e. market_num, which is 20).
        self.stock_mixer = NoGraphMixer(stocks, market) # `stocks` is stock_num, `market` is hidden_dim (e.g. 20)
        
        # This FC layer processes the output of NoGraphMixer.
        # NoGraphMixer output is (batch_of_stocks, calculated_concat_time_dim) if its input was permuted correctly.
        # Input: (B, calculated_concat_time_dim)
        # Output: (B, 1) for the z_out path
        self.time_fc_ = nn.Linear(calculated_concat_time_dim, 1)

    def forward(self, inputs):
        # inputs: (batch_size_is_stock_num, time_steps, channels)
        
        # y_temporal_mixed: (stock_num, calculated_concat_time_dim, channels)
        y_temporal_mixed = self.temporal_mixer(inputs)
        
        # y_channel_processed: (stock_num, calculated_concat_time_dim)
        y_channel_processed = self.channel_fc(y_temporal_mixed).squeeze(-1)
        
        # Path 1: Directly from time-mixed, channel-reduced output
        # y_out: (stock_num, 1)
        y_out = self.time_fc(y_channel_processed)
        
        # Path 2: Through Stock (NoGraph) Mixer
        # NoGraphMixer expects (dim_to_mix_along, other_dim_as_features)
        # It internally permutes. So if we give (stock_num, calculated_concat_time_dim),
        # it permutes to (calculated_concat_time_dim, stock_num), then processes along stock_num.
        # The `stocks` parameter in its init was `stock_num`.
        # The features it operates on for each stock is `calculated_concat_time_dim`.

        # Input to stock_mixer: (stock_num, calculated_concat_time_dim)
        z_stock_mixed = self.stock_mixer(y_channel_processed) 
        # Output of stock_mixer: (stock_num, calculated_concat_time_dim) 
        # (assuming NoGraphMixer is written to preserve the feature dim, which it does via its dense layers)
        
        # z_out: (stock_num, 1)
        z_out = self.time_fc_(z_stock_mixed)
        
        return y_out + z_out
```

`y_channel_processed` 的形状是 `(stock_num, calculated_concat_time_dim)`。
如果将此直接传递给 `self.stock_mixer(y_channel_processed)`，那么在 `NoGraphMixer` 内部：
`x` 是 `(stock_num, calculated_concat_time_dim)`。
`x.permute(1,0)` 后是 `(calculated_concat_time_dim, stock_num)`。
`self.layer_norm_stock = nn.LayerNorm(stocks)`，其中 `stocks` 在初始化时是 `stock_num`。所以 `LayerNorm` 会试图在维度大小为 `stock_num` 的维度上操作。
`self.dense1 = nn.Linear(stocks, hidden_dim)`，其中 `stocks` 是 `stock_num`。这意味着 `dense1` 期望其输入的最后一个维度的大小是 `stock_num`。

2.  **`MultTime2dMixer(nn.Module)`** (这个模块在你的原始 `StockMixer` 中被使用):
    *   **思路**: 它接收两个输入 `inputs` (原始时间序列) 和 `y` (通常是 `inputs` 经过一次 `Conv1d(kernel=2, stride=2)` 下采样后的结果)。

    *   **融合方式**: `MultTime2dMixer` 的 `forward` 方法返回 `torch.cat([inputs, x, y], dim=1)`，其中 `x` 是 `inputs` 经过 `mix_layer` 的结果，`y` 是（作为输入的）下采样序列经过 `scale_mix_layer` 的结果。这里的 `dim=1` 如果输入是 `(B, T, C)`，那么拼接的是**时间维度**。
    *   **特点**: 这个模块更像是一个双尺度处理器（原始尺度 + 一个固定下采样尺度），并且它将原始输入、原始输入处理后的结果、下采样输入处理后的结果一起在时间维度上拼接。结构相对固定。

**我们实现的 `MultiScaleTimeMixerRevised` 的主要区别：**

1.  **更灵活的尺度配置 (`scales_config`)**:
    *   我们的 `MultiScaleTimeMixerRevised` 通过一个 `scales_config` 列表来动态构建任意数量和配置的尺度分支（原始分支和不同 `kernel_size`/`stride` 的卷积分支）。这比 `MultTime2dMixer` 的固定双尺度或 `MultiScaleTimeMixer` 中略显固定的 `2**i` 规则更具通用性。
    *   我们明确计算了每个卷积分支处理后的时间步长 `ts_after_conv`，并用这个精确的时间步长去初始化该分支的 `TriU` 网络，确保 `TriU` 的参数与其实际处理的时间序列长度匹配。

2.  **独立的尺度处理路径**:
    *   在当前版本的 `MultiScaleTimeMixerRevised` 中，**每个尺度分支（无论是原始尺度还是卷积尺度）都接收完整的原始输入 `inputs`**。
    *   卷积分支先对 `inputs` 进行卷积下采样，得到该尺度的特征，然后这个尺度的特征独立通过 `LayerNorm` 和后续的 `TriU` 网络（封装在 `PermuteAndApplyTriUNet` 中）。
    *   原始尺度分支也独立对 `inputs` 进行 `LayerNorm` 和 `TriU` 网络处理。
    *   **当前的融合方式 (我们刚刚讨论其潜在问题并计划修改的)**: 所有这些独立处理后的尺度输出 `(B, T_scale_n, C)` 是在**时间维度 (dim=1) 上进行拼接**，得到 `(B, sum_of_T_scales, C)`。

3.  **与原始 `MultiScaleTimeMixer` 的关键融合差异**:
    *   **原始 `MultiScaleTimeMixer`**: 如果其 `TriU` 输出是 `(B, C, T'_scale_n)`，它在 `dim=-1` (即 `T'` 维度) 拼接，得到 `(B, C, sum_of_T'_scales)`。
    *   **我们当前的 `MultiScaleTimeMixerRevised`**: 输出 `(B, T_scale_n, C)`，在 `dim=1` (即 `T_scale_n` 维度) 拼接，得到 `(B, sum_of_T_scales, C)`。
        本质上，两者最终都是将不同尺度提取的时间信息汇集起来，但具体的维度操作和中间形态可能略有不同，导致了通道和时间维度的不同组合。我们的实现更侧重于保持每个尺度的通道维度 `C` 不变，而将不同尺度的时间表征拼接起来。

4.  **后续处理的设想 (我们下一步要修改的)**:
    *   我们刚才讨论的性能下降，以及SR反常上升的现象，促使我们思考融合方式。
    *   下一步的计划是修改 `MultiScaleTimeMixerRevised`，使得：
        1.  原始输入 `inputs` 和各个卷积分支下采样后的特征（在进入各自的 `TriU` 之前）先进行拼接，形成一个大的多尺度特征图，例如 `(B, sum_of_T_raw_scales, C)`。
        2.  然后，这个**统一的、拼接后的大特征图**再经过一个共享的（或者说单一的）`LayerNorm` 和 `PermuteAndApplyTriUNet` (其内部 `TriU` 网络会用 `sum_of_T_raw_scales` 这个总时间维度初始化)。
    *   **这种修改后的方法与原始的 `MultiScaleTimeMixer` 和我们当前版本的 `MultiScaleTimeMixerRevised` 都有显著不同**。它更强调在早期就将不同尺度的原始特征信息聚合，然后一起进行高级的时序混合。

**总结关键区别点：**

*   **灵活性和配置性**：我们的 `MultiScaleTimeMixerRevised` 在尺度配置上更灵活。
*   **特征输入给各分支的方式**：我们当前版本是每个分支都从最原始的 `inputs` 开始处理。
*   **融合的时机和方式**：
    *   原始的 `MultiScaleTimeMixer`：独立处理各尺度 -> 时间维度拼接（在 `TriU` 输出的最后一个维度）。
    *   我们当前的 `MultiScaleTimeMixerRevised`：独立处理各尺度 -> 时间维度拼接（在 `TriU` 输出的中间时间维度）。
    *   **我们计划修改的 `MultiScaleTimeMixerRevised`**：获取各尺度原始特征 -> 拼接这些原始特征 -> **然后用一个共享的 `TriU` 网络处理拼接后的整体**。

最后这个计划修改的版本，其核心思想是“先聚合多尺度原始信息，再统一深度处理”，这与“各尺度独立深度处理后，再聚合结果”是不同的信息流。这可能是改善性能的关键。

```python
class MultiScaleTimeMixerRevised(nn.Module):
    def __init__(self, initial_time_steps, channels, scales_config, activation_fn_class=nn.Hardswish):
        super().__init__()
        self.channels = channels
        self.initial_time_steps = initial_time_steps

        self.conv_layers = nn.ModuleList()
        self.scale_specific_lns = nn.ModuleList() # To normalize features of each scale before concat
        
        concat_time_dim_for_triu = 0

        # Branch 1: Original scale
        self.scale_specific_lns.append(nn.LayerNorm([initial_time_steps, channels]))
        concat_time_dim_for_triu += initial_time_steps

        # Convolutional scales
        for scale_info in scales_config:
            if scale_info['type'] == 'conv':
                # ts_after_conv for this scale_info is already pre-calculated in StockMixer
                # and is present in scale_info['time_steps']
                ts_after_conv = scale_info['time_steps']
                if ts_after_conv <= 0:
                    continue
                
                self.conv_layers.append(
                    nn.Conv1d(in_channels=channels, out_channels=channels,
                              kernel_size=scale_info['kernel'], stride=scale_info['stride'])
                )
                self.scale_specific_lns.append(nn.LayerNorm([ts_after_conv, channels]))
                concat_time_dim_for_triu += ts_after_conv
            elif scale_info['type'] == 'original':
                # Already handled above, or can ensure config only has one original type
                pass 

        if concat_time_dim_for_triu == 0:
            # This case should be prevented by StockMixer's validation of scales_config
            # and calculated_concat_time_dim. If it occurs, model is misconfigured.
            raise ValueError("MultiScaleTimeMixerRevised: concat_time_dim_for_triu is 0. No valid scales.")

        # Single, shared TriU network that processes the concatenated multi-scale features
        triu_network = nn.Sequential(
            TriU(concat_time_dim_for_triu),
            activation_fn_class(),
            TriU(concat_time_dim_for_triu)
        )
        
        # This LayerNorm is applied to the fully concatenated tensor before TriU processing
        self.final_ln_before_permute = nn.LayerNorm([concat_time_dim_for_triu, channels])
        self.shared_permute_and_triu = PermuteAndApplyTriUNet(triu_network)

    def forward(self, inputs):
        # inputs: (batch_size, initial_time_steps, channels)
        
        extracted_scale_features = []

        # Original scale feature extraction
        original_scale_feat = self.scale_specific_lns[0](inputs) # Apply initial LN
        extracted_scale_features.append(original_scale_feat)

        # Convolutional scale feature extraction
        conv_input = inputs.permute(0, 2, 1) # (B, C, initial_T)
        ln_idx = 1 # Start from the second LayerNorm in self.scale_specific_lns
        for conv_layer in self.conv_layers:
            convolved_feat = conv_layer(conv_input) # (B, C, T_conv_scale)
            convolved_feat_permuted = convolved_feat.permute(0, 2, 1) # (B, T_conv_scale, C)
            
            # Apply the corresponding LayerNorm for this scale
            # Need to ensure self.scale_specific_lns matches self.conv_layers in length for conv scales
            if ln_idx < len(self.scale_specific_lns):
                normed_convolved_feat = self.scale_specific_lns[ln_idx](convolved_feat_permuted)
                extracted_scale_features.append(normed_convolved_feat)
                ln_idx += 1
            else:
                # This should not happen if __init__ is correct
                extracted_scale_features.append(convolved_feat_permuted) 

        # Concatenate all extracted features along the time dimension (dim=1)
        # Each feature is (B, T_scale, C)
        # Concatenated: (B, concat_time_dim_for_triu, C)
        if not extracted_scale_features:
            # Should be caught by __init__'s check on concat_time_dim_for_triu
            raise RuntimeError("No features extracted. Check scales_config and model setup.")
        
        concatenated_features = torch.cat(extracted_scale_features, dim=1)
        
        # Apply final LayerNorm on the big concatenated tensor
        normed_concatenated_features = self.final_ln_before_permute(concatenated_features)
        
        # Process through the shared TriU network
        output = self.shared_permute_and_triu(normed_concatenated_features)
        
        return output
```

```python
class MultiScaleTimeMixerRevised(nn.Module):
    def __init__(self, initial_time_steps, channels, scales_config, activation_fn_class=nn.Hardswish):
        super().__init__()
        self.channels = channels
        self.initial_time_steps = initial_time_steps

        self.conv_layers = nn.ModuleList()
        # REMOVED: self.scale_specific_lns = nn.ModuleList()
        
        concat_time_dim_for_triu = 0

        # Branch 1: Original scale contribution to concat_time_dim
        concat_time_dim_for_triu += initial_time_steps

        # Convolutional scales
        for scale_info in scales_config:
            if scale_info['type'] == 'conv':
                ts_after_conv = scale_info['time_steps']
                if ts_after_conv <= 0:
                    continue
                
                self.conv_layers.append(
                    nn.Conv1d(in_channels=channels, out_channels=channels,
                              kernel_size=scale_info['kernel'], stride=scale_info['stride'])
                )
                # REMOVED: Corresponding LayerNorm for this scale
                concat_time_dim_for_triu += ts_after_conv
            elif scale_info['type'] == 'original':
                pass 

        if concat_time_dim_for_triu == 0:
            raise ValueError("MultiScaleTimeMixerRevised: concat_time_dim_for_triu is 0. No valid scales.")

        triu_network = nn.Sequential(
            TriU(concat_time_dim_for_triu),
            activation_fn_class(),
            TriU(concat_time_dim_for_triu)
        )

        self.shared_permute_and_triu = PermuteAndApplyTriUNet(triu_network)

        original_scale_feat = inputs

        # Convolutional scale feature extraction
        conv_input = inputs.permute(0, 2, 1) # (B, C, initial_T)
        for conv_layer in self.conv_layers:
            convolved_feat = conv_layer(conv_input) # (B, C, T_conv_scale)
            convolved_feat_permuted = convolved_feat.permute(0, 2, 1) # (B, T_conv_scale, C)
            # REMOVED: No scale-specific LN before concat for this version
            extracted_scale_features.append(convolved_feat_permuted)

        if not extracted_scale_features:

        concatenated_features = torch.cat(extracted_scale_features, dim=1)
        
        normed_concatenated_features = self.final_ln_before_permute(concatenated_features)
        
        output = self.shared_permute_and_triu(normed_concatenated_features)
        
        return output
```

一个可以尝试的策略是更精细地控制 `LayerNorm` 的使用。在上一个版本中，我们移除了所有在拼接前对各尺度特征的 `LayerNorm`，只保留了拼接后的一个 `LayerNorm`。

现在，我们尝试一个折中方案：

1.  **原始尺度特征**：直接使用输入 `inputs`，不进行 `LayerNorm`。
2.  **卷积尺度特征**：每个卷积层提取出的特征，在进行拼接之前，各自通过一个独立的 `LayerNorm`。
3.  **拼接后**：所有尺度（原始尺度 + 经过独立LN的卷积尺度）的特征拼接起来后，再通过我们之前保留的那个最终的 `LayerNorm` (`self.final_ln_before_permute`)。

这个想法的依据是：原始输入特征可能已经具有较好的分布，而卷积操作可能会显著改变特征分布，因此对卷积后的特征进行规范化可能是有益的，然后再将它们与原始特征融合，并进行最终的整体规范化。

下面是对 `src/model.py` 中 `MultiScaleTimeMixerRevised` 类的修改：

我将进行以下操作：

1.  在 `MultiScaleTimeMixerRevised.__init__` 中，为每个卷积分支创建一个对应的 `LayerNorm` 层，存放在一个新的 `nn.ModuleList` 叫做 `self.conv_scale_lns`。
2.  在 `MultiScaleTimeMixerRevised.forward` 中：
    *   原始尺度的特征直接使用 `inputs`。
    *   每个卷积分支的输出在 `permute` 回 `(B, T_conv_scale, C)` 形状后，会先通过其对应的 `self.conv_scale_lns[i]` 进行规范化，然后再加入到待拼接的特征列表中。
    *   最后，拼接好的特征依然会通过 `self.final_ln_before_permute`。



```python

class MultiScaleTimeMixerRevised(nn.Module):
    def __init__(self, initial_time_steps, channels, scales_config, activation_fn_class=nn.Hardswish):
        super().__init__()
        self.channels = channels
        self.initial_time_steps = initial_time_steps

        self.conv_layers = nn.ModuleList()
        self.conv_scale_lns = nn.ModuleList() # LN for each convolutional scale output before concat
        
        concat_time_dim_for_triu = 0

        # Branch 1: Original scale contribution to concat_time_dim
        concat_time_dim_for_triu += initial_time_steps

        # Convolutional scales
        for scale_info in scales_config:
            if scale_info['type'] == 'conv':
                ts_after_conv = scale_info['time_steps']
                if ts_after_conv <= 0:
                    continue
                
                self.conv_layers.append(
                    nn.Conv1d(in_channels=channels, out_channels=channels,
                              kernel_size=scale_info['kernel'], stride=scale_info['stride'])
                )
                self.conv_scale_lns.append(nn.LayerNorm([ts_after_conv, channels]))
                concat_time_dim_for_triu += ts_after_conv
            elif scale_info['type'] == 'original':
                # This part of config is mainly for calculating concat_time_dim_for_triu
                # and for clarity. Original scale features are handled directly from 'inputs'.
                pass 

        if concat_time_dim_for_triu == 0:
            raise ValueError("MultiScaleTimeMixerRevised: concat_time_dim_for_triu is 0. No valid scales.")

        triu_network = nn.Sequential(
            TriU(concat_time_dim_for_triu),
            activation_fn_class(),
            TriU(concat_time_dim_for_triu)
        )
        
        # This LN is applied AFTER concatenating original features and (LN'd) conv features
        self.final_ln_before_permute = nn.LayerNorm([concat_time_dim_for_triu, channels])
        self.shared_permute_and_triu = PermuteAndApplyTriUNet(triu_network)

    def forward(self, inputs):
        # inputs: (batch_size, initial_time_steps, channels)
        
        extracted_scale_features = []

        # Original scale feature (no specific LN before concat for this version)
        original_scale_feat = inputs 
        extracted_scale_features.append(original_scale_feat)

        # Convolutional scale feature extraction
        conv_input = inputs.permute(0, 2, 1) # (B, C, initial_T)
        for i, conv_layer in enumerate(self.conv_layers):
            convolved_feat = conv_layer(conv_input) # (B, C, T_conv_scale)
            convolved_feat_permuted = convolved_feat.permute(0, 2, 1) # (B, T_conv_scale, C)
            
            # Apply LayerNorm specific to this convolutional scale
            normed_convolved_feat = self.conv_scale_lns[i](convolved_feat_permuted)
            extracted_scale_features.append(normed_convolved_feat)

        if not extracted_scale_features: # Should be at least original_scale_feat
            raise RuntimeError("No features extracted. Check scales_config and model setup.")
        
        concatenated_features = torch.cat(extracted_scale_features, dim=1)
        
        # Apply final LayerNorm on the big concatenated tensor
        normed_concatenated_features = self.final_ln_before_permute(concatenated_features)
        
        output = self.shared_permute_and_triu(normed_concatenated_features)
        
        return output
```
